# 完整实现方案（基于方案 A）

## 一、总体架构

采用**单进程架构**：模型在 FastAPI 应用启动（lifespan）时加载一次，常驻内存，所有请求直接进程内调用，不拆 HTTP 服务、不做结果缓存。

```
┌─────────────────────────────── 单个 FastAPI 进程 ───────────────────────────────┐
│                                                                                  │
│  lifespan 启动时加载一次：                                                       │
│    RedisManager ──► 连接 Redis（Lab2）                                           │
│    SensitiveWordChecker ──► 加载敏感词（Lab2）                                   │
│    ModelService ──► 加载 ONNX 模型 + tokenizer（Lab3，常驻内存）                 │
│                                                                                  │
│  对外暴露的业务接口（唯一入口）：                                                 │
│    POST /check  ──► 敏感词命中？──是──► 按 Lab2 返回（found=True）               │
│                              └──否──► 进程内调用 ModelService.predict()          │
│                                      返回识别的意图 intent / intent_score        │
│                                                                                  │
│  模型服务完全内部调用：不对外暴露任何模型推理 HTTP 接口，                         │
│  外部网络根本没有模型推理的原生接口（代码层隔离）                                 │
└──────────────────────────────────────────────────────────────────────────────────┘
```

## 四、模型服务（`src/onnx_deploy/model_service.py`）

核心类 `ModelService`，实现"进程内常驻模型，零 HTTP 序列化开销"：

```python
class ModelService:
    def __init__(
        self,
        bundle_dir=None,
        model_file=None,
        max_length=None,
        provider=None,
        intra_op_threads=None,
    ):
        # 从环境变量读取默认值
        ...

    def load(self) -> None:
        """启动时加载一次：manifest / label_mapping / tokenizer / ONNX 模型"""
        # 1. 读取 manifest.json、label_mapping.json
        # 2. 复用训练阶段固定的 id2label 映射（保证 logits 第 i 维对应正确标签）
        # 3. 从 bundle 本地加载 tokenizer（local_files_only=True，不依赖外网）
        # 4. 创建 InferenceSession（intra_op_num_threads=1，常驻内存）
        ...

    def predict(self, text: str) -> dict:
        """对单条文本做意图识别，返回 intent / score / top_k"""
        # 1. 文本归一化（NFKC + 去空白，与训练阶段一致）
        # 2. tokenizer 编码
        # 3. session.run(["logits"], inputs) 前向推理
        # 4. softmax 转概率，top-k 解码
        ...
```

关键点：
- **模型只加载一次**：`load()` 在 lifespan 里调用，`InferenceSession` 常驻内存，后续 `predict()` 复用，不重复加载。
- **复用 `infer_onnx_offline.py` 的推理逻辑**：归一化、softmax、top-k、`build_session_inputs` 等逻辑保持一致，保证线上效果与离线验证一致。
- **模型路径回退**：优先用 manifest 里的量化模型 `model.int8.onnx`，若 bundle 里不存在则回退到原始 `model.onnx`。
- **不依赖 PyTorch**：只用 `onnxruntime` + `transformers` 的 tokenizer。

## 五、业务接口（`src/check/api.py`）

### 1. lifespan 加载模型

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    password = await get_redis_password()  # 1. 拿密码（Lab2）
    rm = RedisManager(REDIS_ADDRESSES, password, max_connections=MAX_CONNECTIONS)
    await rm.start()
    app.state.redis_manager = rm
    checker = SensitiveWordChecker(rm)  # 2. 加载敏感词（Lab2）
    await checker.load()
    app.state.word_checker = checker

    # Lab3: 3. 进程内常驻加载意图识别模型（只加载一次，常驻内存）
    model = ModelService()
    model.load()
    app.state.model_service = model

    try:
        yield
    finally:
        await rm.stop()
```

### 2. 对外业务接口 `POST /check`

**核心逻辑**：敏感词命中 → 按 Lab2 返回；敏感词未命中 → 调用模型推理返回意图。

```python
class CheckResponse(BaseModel):
    text: str
    found: bool
    matched: list[str]
    # Lab3: 意图识别结果（仅当敏感词未命中时由模型推理得到）
    intent: Optional[str] = None
    intent_score: Optional[float] = None


@check_router.post("/check", response_model=CheckResponse)
async def check(req: CheckRequest, request: Request):
    try:
        checker: SensitiveWordChecker = request.app.state.word_checker
        matched = checker.check(req.text)

        # Lab3: 意图识别 —— 仅当敏感词未命中时才调用模型推理
        intent: Optional[str] = None
        intent_score: Optional[float] = None

        if not matched:
            model: ModelService = request.app.state.model_service
            result = model.predict(req.text)
            intent = result["intent"]
            intent_score = result["score"]

    except Exception as exc:
        raise HTTPException(status_code=503, detail=f"check failure: {exc}")
    return CheckResponse(
        text=req.text,
        found=len(matched) > 0,
        matched=matched,
        intent=intent,
        intent_score=intent_score,
    )
```

### 3. 模型服务完全内部调用（不对外暴露）

模型服务**不对外提供任何 HTTP 接口**，客户端只通过 `/check` 调用，服务端在进程内直接调用 `ModelService.predict()`。外部网络根本没有模型推理的原生接口，实现"代码层隔离"。
